2. 실험 환경 및 방법
데이터: rand()로 0 ~ 1,000,000 범위의 무작위 정수를 생성 (중복 허용), 시드 고정(srand(2026))
데이터 크기 n: 1,000 / 2,000 / 4,000 / 8,000 / 16,000 / 20,000
각 데이터 크기마다 원본 배열을 한 번 생성하고, 모든 알고리즘이 동일한 원본의 복사본을 정렬
정렬은 오름차순이며, 정렬 후 qsort로 만든 정답 배열과 모든 원소를 비교하여 정렬 결과를 검증
컴파일 옵션: gcc -O2
2.1 숫자 비교 횟수 측정 기준
배열 원소 값끼리 비교할 때마다 전역 카운터를 1 증가시킨다.
힙 정렬: 힙 구성(build heap)과 정렬 단계의 힙 속성 복구(sift-down)에서 발생하는 비교를 모두 포함 (두 자식 중 큰 값 선택 1회 + 부모와 큰 자식 비교 1회).
병합 정렬: 병합 과정에서 a[i] <= a[j] 비교만 카운트.
퀵 정렬: 분할 과정의 a[i] < pivot, a[j] > pivot 비교와, Median-of-Three의 피벗 선택 비교(2~3회)를 포함. 반복문의 인덱스 검사(i <= j, child < end 등)와 종료 조건 검사는 제외.
2.2 실행시간 측정 기준
clock_gettime(CLOCK_MONOTONIC)로 정렬 함수 호출 직전과 직후의 시각 차이를 ms 단위로 측정.
데이터 생성, 배열 복사, 결과 검증, 출력 시간은 제외. 모든 알고리즘에 같은 방법과 단위를 적용.
각 조건을 1회 실행한 값이므로 n이 작을 때(1ms 미만)는 측정 오차(잡음)가 상대적으로 크다.
2.3 메모리 사용량 측정 기준 (직접 계산 방식)

프로파일링 도구 대신 64비트 환경 기준으로 직접 계산하였다. 원본 데이터 배열은 공통 비용이므로 제외하고, 정렬 중 필요한 최대 추가 메모리만 계산한다.

기본 크기: int = 4 Byte, 포인터 = 8 Byte, 반환 주소 = 8 Byte

알고리즘	계산식	설명
힙 정렬	20 Byte (고정)	재귀가 없고 입력 배열을 그대로 힙으로 사용. 보조 변수 int 5개(n, parent, child, end, 교환용 임시 변수) × 4 Byte
병합 정렬	n × 4 + (최대 재귀 깊이) × 48	임시 배열 n × 4 Byte + 재귀 호출 1회당 스택 프레임 48 Byte (반환 주소 8 + 포인터 2개 16 + lo, mid, hi 12 + i, j, k 12)

최대 재귀 깊이는 프로그램이 실행 중에 직접 추적하여(cur_depth, max_depth) 계산에 사용하였다.

4. 비교·분석
4.1 데이터 크기 증가에 따른 비교 횟수 변화

n이 1,000에서 20,000으로 20배 커지는 동안 비교 횟수는 힙 정렬이 16,841 → 510,475(약 30.3배), 병합 정렬이 8,726 → 260,812(약 29.9배), 퀵 정렬(First)이 11,123 → 341,275(약 30.7배) 증가하였다. 세 알고리즘 모두 n이 20배일 때 약 30배 늘었는데, 이는 O(n)(20배)보다 크고 O(n²)(400배)보다 훨씬 작다. n log₂ n의 증가 비율이 20 × (14.29 / 9.97) ≈ 28.7배인 것과 거의 일치하므로, 세 알고리즘 모두 실험적으로 O(n log n)에 해당하는 증가 양상을 보인다.

알고리즘 사이의 차이는 동작 방식으로 설명된다.

병합 정렬은 구간을 반으로 나누고 두 정렬된 구간을 앞에서부터 한 번씩만 비교하며 합치므로 비교 횟수가 가장 적다. n = 20,000에서 260,812회로 n log₂ n(약 285,700)에 가깝다.
힙 정렬은 sift-down 한 단계마다 "두 자식 비교"와 "부모와 큰 자식 비교"를 모두 수행하므로 단계당 비교가 2회이다. 그 결과 모든 크기에서 병합 정렬의 약 1.9~2.0배(n = 20,000에서 510,475 / 260,812 ≈ 1.96배)로 비교 횟수가 가장 많았다.
퀵 정렬은 피벗을 기준으로 분할하면서 각 원소를 피벗과 한 번씩 비교한다. 피벗이 항상 정확히 가운데로 나뉘지는 않으므로 병합 정렬보다 많고(n = 20,000에서 약 1.25~1.31배), 힙 정렬보다는 적다.
4.2 실행시간 차이

n = 20,000에서 퀵 정렬(First) 1.301ms가 가장 빠르고, 힙 정렬 1.640ms와 병합 정렬 1.658ms는 거의 같으며, 퀵 정렬(First)은 힙 정렬보다 약 20% 빠르다. 같은 경향이 n = 8,000 이상에서 일관되게 나타났다.

퀵 정렬은 비교 횟수가 병합 정렬보다 많은데도 가장 빠르다. 제자리(in-place)로 분할하므로 임시 배열로 복사하고 되돌리는 작업이 없고, 양 끝에서 인접한 원소를 순차적으로 읽어 메모리 접근 패턴이 캐시에 유리하기 때문이다. 즉 실행시간은 비교 횟수만이 아니라 데이터 이동량과 메모리 접근 방식의 영향도 크다.
병합 정렬은 비교 횟수가 가장 적지만, 병합마다 값을 임시 배열에 쓰고 다시 원래 배열로 복사하므로 이동 횟수가 많아 비교 횟수의 이점이 시간 단축으로 이어지지 않았다.
힙 정렬은 비교 횟수가 병합 정렬의 약 2배인데도 시간이 비슷했다. 비교 횟수는 많지만 데이터 이동이 적고 추가 배열이 없기 때문이다. 다만 sift-down에서 인덱스가 2i+1처럼 멀리 건너뛰며 접근하므로 캐시 효율은 좋지 않다.

주의: 전체 시간이 1~2ms 수준이고 1회 측정이므로, n이 작은 구간(특히 1,000~4,000)의 알고리즘 간 시간 차이는 측정 오차 범위 안에 있다. 예를 들어 n = 2,000에서 Quick(Median3)이 0.183ms로 다른 크기의 경향보다 크게 나온 것은 잡음으로 보인다. 따라서 시간은 n이 큰 구간의 경향을 중심으로 해석하였다.

4.3 메모리 사용량 차이

n = 20,000에서 병합 정렬은 80,768Byte, 퀵 정렬은 864~1,224Byte, 힙 정렬은 20Byte였다.

병합 정렬: 메모리의 대부분이 임시 배열(20,000 × 4 = 80,000Byte)이며 n에 비례하여 증가한다 (4,528 → 8,576 → 16,624 → 32,672 → 64,720 → 80,768). 재귀 스택은 깊이 16 × 48 = 768Byte로 매우 작다.
퀵 정렬: 임시 배열이 없고 재귀 스택만 사용한다. 최대 깊이가 약 24~34이므로 36Byte × 깊이 = 864~1,224Byte이며 n이 20배 커져도 약 2배밖에 늘지 않았다(깊이가 log n에 가깝게 증가).
힙 정렬: 재귀가 없고 입력 배열 자체를 힙으로 사용하므로 모든 n에서 20Byte로 일정하다(O(1)).
4.4 퀵 정렬의 피벗 선택 방법에 따른 차이
비교 횟수: n = 20,000에서 First 341,275, Random 338,906, Median3 327,061로 Median3이 가장 적었다. 6개 데이터 크기 중 Median3이 가장 적은 경우는 4번(2,000 / 8,000 / 16,000 / 20,000), Random이 가장 적은 경우는 2번(1,000 / 4,000)이었다. 세 원소의 중앙값을 쓰면 피벗이 극단값이 될 가능성이 줄어 분할이 더 균형 있게 되기 때문이다. 다만 피벗 선택에 비교가 2~3회 추가로 들기 때문에 이득이 크지 않고 n이 작을 때는 오히려 손해일 수 있다(n = 1,000에서 Random이 더 적음).
메모리(재귀 깊이): Median3이 모든 크기에서 가장 작은 스택 사용량(576 ~ 864Byte)을 보였다. 분할이 균형 잡힐수록 재귀 깊이가 얕아지기 때문이다. First와 Random은 깊이가 더 깊어 1,000 ~ 1,260Byte 수준이었다.
실행시간: 세 방법 모두 n = 20,000에서 1.3 ~ 1.5ms로 큰 차이가 없었다. 무작위 데이터에서는 First 피벗도 평균적으로 잘 동작하며, Random은 난수 생성 비용(rand() 호출)이 추가되어 오히려 약간 느리게 나왔다.
이번 실험은 무작위 데이터만 사용했으므로 First 피벗이 최악이 되는 이미 정렬된 데이터(O(n²))에서의 차이는 나타나지 않았다. 그러한 입력에서는 Random과 Median3이 안정적이다.
4.5 시간 복잡도 및 공간 복잡도 비교
알고리즘	최선	평균	최악	공간 복잡도	안정성
힙 정렬	O(n log n)	O(n log n)	O(n log n)	O(1)	불안정
병합 정렬	O(n log n)	O(n log n)	O(n log n)	O(n)	안정
퀵 정렬	O(n log n)	O(n log n)	O(n²)	O(log n) (평균), O(n) (최악 재귀 깊이)	불안정

실험 결과는 이 이론과 일치한다. 세 알고리즘의 비교 횟수와 시간이 모두 n log n 수준으로 증가했고, 공간은 힙 정렬 O(1)(20Byte 고정), 퀵 정렬 O(log n)(깊이 증가가 완만), 병합 정렬 O(n)(임시 배열에 비례)로 나타났다.

4.6 종합
기준	가장 유리한 알고리즘	이유
비교 횟수	병합 정렬	정렬된 두 구간을 한 번씩만 비교하며 병합
실행시간	퀵 정렬	제자리 분할로 데이터 이동이 적고 캐시 효율이 좋음
메모리	힙 정렬	입력 배열 자체를 힙으로 사용, 추가 공간 O(1)
최악 성능 보장	힙 정렬, 병합 정렬	입력과 관계없이 O(n log n) 보장

따라서 평균적인 속도가 중요하면 퀵 정렬, 추가 메모리가 제한되면서 최악 성능도 보장해야 하면 힙 정렬, 안정 정렬이 필요하거나 비교 횟수 자체를 줄여야 하면 병합 정렬이 적합하다.
